## ✨ 功能特色

### 核心功能
- **高效壓縮**：使用 H.265 (HEVC) 或 H.264 編碼，可將 2-5GB 的影片壓縮至數百 MB
- **保持畫質**：CRF (Constant Rate Factor) 技術確保壓縮時維持高畫質
- **保持解析度**：不會縮放影片，維持原始解析度（確保長寬不低於 1000px）
- **批次處理**：支援同時處理多個檔案
- **即時進度**：顯示轉檔進度和預估完成時間

### 支援格式

| 類型 | 支援格式 |
|------|----------|
| **輸入格式** | MOV, MP4, MPG/MPEG, WMV, WebM, AVI, MKV, FLV, M4V, 3GP |
| **輸出格式** | MP4, WebM, MKV, AVI |

### 編碼器選項

| 編碼器 | 說明 | 適用場景 |
|--------|------|----------|
| **H.265 (HEVC)** | 最新的壓縮標準，壓縮效率最高 | 需要最小檔案的場合 |
| **H.264** | 兼容性最好的編碼器 | 需要廣泛兼容性的場合 |
| **VP9** | Google 開發的開源編碼器 | 網頁影片使用 |

## 💻 系統需求

- **作業系統**：macOS 10.13 (High Sierra) 或更新版本
- **處理器**：Intel 或 Apple Silicon (M1/M2/M3)
- **記憶體**：4GB RAM 或以上（建議 8GB 以上處理大檔案）
- **磁碟空間**：約 300MB（應用程式 + 依賴套件）
- **Node.js**：v18.0.0 或更新版本

## 📥 安裝方式

### 方法一：從原始碼安裝（開發者）

#### 1. 複製專案

```bash
git clone https://github.com/miku4ocean/mac-video-transfer.git
cd mac-video-transfer
```

#### 2. 安裝依賴套件

```bash
npm install
```

> ⚠️ **注意**：首次安裝可能需要幾分鐘，因為需要下載 FFmpeg 二進位檔案。

#### 3. 啟動應用程式

```bash
npm run dev
```

### 方法二：建置安裝檔

#### 建置 DMG 安裝檔

```bash
npm run build:dmg
```

建置完成後，安裝檔位於 `dist/` 目錄中。

#### 建置 ZIP 壓縮檔

```bash
npm run build
```

## 📖 使用說明

### 基本操作流程

#### 步驟 1：新增影片檔案

有兩種方式可以新增檔案：

1. **拖放檔案**：直接將影片檔案拖放到應用程式視窗中
2. **選擇檔案**：點擊「選擇檔案」按鈕，從檔案對話框選擇

![拖放區域](docs/drop-zone.png)

#### 步驟 2：調整壓縮設定

在左側面板調整以下設定：

| 設定項目 | 說明 | 建議值 |
|----------|------|--------|
| **輸出格式** | 選擇輸出檔案格式 | MP4（兼容性最佳） |
| **編碼器** | 選擇視訊編碼器 | H.265（壓縮率最高） |
| **壓縮品質** | CRF 值，數值越低畫質越高 | 23-25（平衡） |
| **編碼速度** | 編碼預設，越慢檔案越小 | medium（平衡） |
| **保持原始音訊** | 不重新編碼音訊 | 勾選（保持音質） |

#### 步驟 3：快速預設

使用快速預設一鍵設定：

| 預設 | CRF 值 | 編碼速度 | 適用場景 |
|------|--------|----------|----------|
| ✨ **高畫質** | 20 | slow | 需要最佳畫質 |
| ⚖️ **平衡** | 25 | medium | 一般用途（推薦） |
| 📦 **小檔案** | 30 | fast | 需要最小檔案 |

#### 步驟 4：開始轉檔

1. 確認檔案清單中的檔案
2. 點擊「開始轉檔」按鈕
3. 選擇輸出檔案位置
4. 等待轉檔完成

#### 步驟 5：查看結果

轉檔完成後，可以：

- 點擊「播放」直接播放轉換後的影片
- 點擊「開啟資料夾」在 Finder 中顯示檔案
- 查看壓縮前後的檔案大小對比

## 🔧 技術說明

### CRF (Constant Rate Factor) 說明

CRF 是一種品質控制方式，它會根據影片內容自動調整位元率：

| CRF 範圍 | 品質描述 |
|----------|----------|
| 0-17 | 無損/近無損（檔案很大） |
| 18-23 | 高畫質（推薦） |
| 24-28 | 中等畫質 |
| 29-35 | 低畫質（明顯壓縮痕跡） |
| 36-51 | 非常低品質 |

### 編碼預設說明

| 預設 | 編碼速度 | 壓縮效率 | 適用場景 |
|------|----------|----------|----------|
| ultrafast | 最快 | 最低 | 快速預覽 |
| fast | 快 | 較低 | 一般用途 |
| medium | 中等 | 中等 | **推薦預設** |
| slow | 慢 | 較高 | 最終輸出 |
| veryslow | 最慢 | 最高 | 追求最小檔案 |

## ❓ 常見問題

### Q1：轉檔速度很慢怎麼辦？

**A**：可以嘗試以下方法：
1. 使用 H.264 編碼器（比 H.265 快 2-3 倍）
2. 選擇較快的編碼預設（如 `fast` 或 `ultrafast`）
3. 確保電腦沒有執行其他高 CPU 使用率的程式

### Q2：轉檔後畫質有明顯下降？

**A**：嘗試降低 CRF 值（數值越低畫質越高）：
- 對於重要影片，使用 CRF 18-20
- 對於一般用途，使用 CRF 23-25

### Q3：輸出的影片無法播放？

**A**：可能的解決方案：
1. 使用 MP4 格式搭配 H.264 編碼器（兼容性最佳）
2. 確認播放器支援 H.265/HEVC 編碼
3. 嘗試使用 VLC 播放器

### Q4：應用程式無法啟動？

**A**：請確認：
1. macOS 版本為 10.13 或更新
2. 已安裝 Node.js v18 或更新版本
3. 已正確執行 `npm install`

### Q5：如何處理超大檔案（10GB+）？

**A**：建議：
1. 使用 H.265 編碼器獲得最佳壓縮
2. 選擇 `slow` 或 `veryslow` 預設
3. 確保有足夠的磁碟空間（至少原始檔案大小的 2 倍）
4. 耐心等待，大檔案可能需要較長時間
